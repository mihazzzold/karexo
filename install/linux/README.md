# 🐧 Установка karexo на Linux без Docker

Один файл: приложение внутри него, папки со статикой рядом нет. Нужен Linux с systemd
(Debian, Ubuntu, RHEL, Fedora, Astra и т. п.) и права root.

---

## 📦 Установка

Распакуйте архив и запустите:

```bash
sudo ./install.sh
```

Скрипт сделает всё сам: заведёт служебного пользователя `karexo` без права входа в систему,
создаст каталоги, **сгенерирует ключ шифрования** и поднимет службу. Ничего вводить не нужно.

Дальше два шага:

1. впишите свой адрес в `/etc/karexo/karexo.env` (строка `KAREXO_BASE_URL`);
2. `sudo systemctl restart karexo`.

Откройте адрес. **Первый зарегистрированный аккаунт становится владельцем инстанса** -
регистрируйтесь сразу.

---

## 🗂️ Что и куда легло

| Путь | Что это |
|---|---|
| `/usr/local/bin/karexo-server` | Сам сервер вместе с приложением - один файл |
| `/var/lib/karexo/` | **Все данные**: база и вложения. Это и есть то, что нужно копировать |
| `/etc/karexo/karexo.env` | Настройки. Права `640`: внутри пароль от почты |
| `/etc/systemd/system/karexo.service` | Служба |

---

## 🔄 Обновление

Скачайте новый архив, распакуйте и запустите тот же скрипт:

```bash
sudo ./install.sh
```

Он подменит бинарь и перезапустит службу. **Настройки и данные не трогаются**, ключ шифрования
не перезаписывается. Если служба не поднялась, скрипт покажет журнал и не станет уверять, что
всё хорошо.

Проверить версию, не запуская сервер:

```bash
karexo-server -version
```

## 🔐 HTTPS

Три пути. Первый - если обратного прокси у вас нет и ставить его некому.

### Сам karexo получает сертификат

Впишите в `/etc/karexo/karexo.env`:

```
KAREXO_TLS=auto
KAREXO_TLS_DOMAIN=notes.example.org
KAREXO_TLS_EMAIL=admin@example.org
KAREXO_ADDR=:80
```

Нужны публичный домен, указывающий на эту машину, и **открытые снаружи порты 80 и 443**: по 80
идёт проверка владения доменом. Порты ниже 1024 службе без root недоступны - раскомментируйте в
юните строку `AmbientCapabilities=CAP_NET_BIND_SERVICE`:

```bash
sudo systemctl edit --full karexo   # снять # со строки AmbientCapabilities
sudo systemctl restart karexo
```

Сертификаты лягут в `/var/lib/karexo/certs` и будут продлеваться сами.

### Свой сертификат

Для закрытого контура и для сертификата своего центра сертификации:

```
KAREXO_TLS=file
KAREXO_TLS_CERT=/etc/karexo/tls.crt
KAREXO_TLS_KEY=/etc/karexo/tls.key
```

Обновлённый на диске сертификат подхватывается **без перезапуска** - в течение минуты.

⚠️ `KAREXO_TLS=auto` в закрытом контуре не заработает и не должен: получение сертификата - это
обращение к Let's Encrypt. При `KAREXO_ALLOW_OUTBOUND=false` служба откажется стартовать и
скажет об этом прямо, а не пойдёт наружу тайком.

### За обратным прокси

Оставьте `KAREXO_TLS=off` (по умолчанию) - шифрование обеспечит прокси. Быстрее всего Caddy: он
сам получает сертификат.

```caddyfile
notes.example.org {
    reverse_proxy localhost:8080
}
```

После этого добавьте в `/etc/karexo/karexo.env`:

```
KAREXO_TRUST_PROXY=true
```

⚠️ Только при работе за прокси. Если сервер смотрит в интернет напрямую, оставьте строку
закомментированной: заголовок `X-Forwarded-Proto` присылает клиент, и включённое доверие
позволяет ему заставить сессионную куку уехать по открытому каналу.

## 💾 Резервные копии

**Вручную** - кнопка «Резервная копия» в разделе «Сервер».

**По расписанию** - три строки в `/etc/karexo/karexo.env`:

```
KAREXO_BACKUP_DIR=/var/lib/karexo/backups
KAREXO_BACKUP_EVERY=24h
KAREXO_BACKUP_KEEP=7
```

**Целиком каталог** - если забираете копию снаружи, остановите службу на время копирования:

```bash
sudo systemctl stop karexo
sudo tar czf karexo-backup.tar.gz -C /var/lib/karexo .
sudo systemctl start karexo
```

Проверить, что архив годен, можно не разворачивая его:

```bash
karexo-server -verify-backup /путь/к/копии.zip
```

---

## 🧹 Снятие

```bash
sudo ./install.sh --uninstall
```

Убирает службу и бинарь. **Данные и настройки остаются** - удалите их сами, если они больше
не нужны:

```bash
sudo rm -rf /var/lib/karexo /etc/karexo
```

## ❓ Если что-то не так

| Симптом | Что смотреть |
|---|---|
| Служба не поднимается | `journalctl -u karexo -n 50` - при ошибке настройки сервер называет переменную |
| Не приходят письма | Не заданы `KAREXO_SMTP_*`. Проверка настроек - в разделе «Сервер» |
| Приглашение ведёт не туда | `KAREXO_BASE_URL` не совпадает с реальным адресом |
| Просит войти после каждого обновления страницы | За прокси нужен `KAREXO_TRUST_PROXY=true`, а сам прокси обязан передавать `X-Forwarded-Proto` |
| «permission denied» в журнале | Служба намеренно может писать только в `/var/lib/karexo`. Каталог за его пределами (например `KAREXO_BACKUP_DIR`) нужно добавить в `ReadWritePaths` юнита |
