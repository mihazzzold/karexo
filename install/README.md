# 🚀 Установка karexo на свой сервер

База знаний из блоков, которая живёт **на вашей машине**. Ваши заметки не уходят к нам:
мы не видим ни текста, ни того, что инстанс вообще запущен.

**Времени:** пять минут.

Путей установки ровно **два** - выбирается по тому, что у вас за машина:

| | Чем ставить | Что получится | Нужно |
|---|---|---|---|
| 🐧 **Сервер** (Linux, любой контейнерный хост) | `install.sh` - один скрипт | стек Docker Compose | Docker, 1 ГБ памяти |
| 🪟 **Windows** | мастер с формой (`karexo_..._windows_server_setup.exe`) - 🧊 **со страницы выпуска снят**, см. ниже | служба Windows | ничего сверх самой Windows |

Оба пути настраивают одно и то же: переменные `KAREXO_*`. Инстанс, поднятый одним способом,
настраивается так же, как поднятый другим.

---

## 📦 Установка скриптом (Linux, Docker)

```bash
curl -fsSLO https://raw.githubusercontent.com/mihazzzold/karexo/main/install/install.sh
sh install.sh
```

Скрипт спросит адрес, порт и почту, **сам сгенерирует ключ шифрования**, запишет `.env` с правами
600, поднимет стек и дождётся ответа сервера. Файл `docker-compose.yml` он возьмёт рядом с собой,
а если его нет - скачает.

Неинтерактивно (ansible, повторяемая установка) - флагами, а секреты через окружение, чтобы они
не попали в историю оболочки и в `ps`:

```bash
KAREXO_SMTP_PASS=... sh install.sh --yes \
    --base-url https://notes.example.org \
    --port 8080 --registration invite \
    --smtp-host smtp.example.org --smtp-user karexo@example.org
```

Что ещё умеет: `--update` (обновиться), `--uninstall` (снять стек, данные остаются),
`--env-only` (собрать `.env` и не поднимать), `--offline` (закрытый контур), `--help`.

### 👤 Владелец заводится отдельной командой

Скрипт спросит и **учётку владельца** - заведёт её сразу, вход будет по почте и паролю.
**Отвечать на этот вопрос надо.** Регистрация по умолчанию `invite`: формы
«Зарегистрироваться» на инстансе нет вовсе, а пригласить первого человека некому - база
пуста. Пропустите вопрос - получите поднятый инстанс, в который нечем войти.

Ставите не скриптом, а руками (`docker compose up -d`)? Владельца заводит сам сервер, до
первого входа:

```bash
printf '%s\n' 'пароль-не-короче-8' | docker compose exec -T karexo \
    karexo-server -create-owner -data /data -owner-email you@example.org
```

Пароль идёт в stdin, а не флагом: аргументы видны в `ps` и в `docker inspect` любому, у кого
есть доступ к докеру. Повторный запуск на непустой базе ничего не меняет (код возврата 10).

При `KAREXO_REGISTRATION=open` владельцем станет тот, кто ПЕРВЫМ откроет адрес и
зарегистрируется - на публичном адресе это гонка с кем угодно, кто узнал про инстанс раньше вас.

⚠️ **Адрес в настройках сайт не создаёт.** `KAREXO_BASE_URL` нужен, чтобы письма и публичные
ссылки вели куда надо. Чтобы адрес открывался, доменом надо распорядиться самому: A-запись в DNS
на этот сервер, открытый порт и - если нужен HTTPS - `nginx`/`Caddy` перед karexo либо режим
`KAREXO_TLS=auto`.

## 🪟 Установка на Windows (мастер)

> 🧊 **С 16.10.2026 мастер на страницу выпуска не прикладывается**: он не прошёл проверку и не
> подписан (Windows SmartScreen предупреждает на каждой установке). Код сохранён - вернём, когда
> появятся проверка и подпись кода. Собрать мастер руками можно: `make installer`.

Запустите `karexo_<версия>_windows_server_setup.exe`. Мастер
спросит согласие администратора, покажет форму (адрес, порт, доступ, почта, HTTPS, дополнительно)
и после нажатия поставит **службу Windows**:

| Что | Куда |
|---|---|
| Программа | `%ProgramFiles%\karexo\karexo-server.exe` |
| Данные | `%ProgramData%\karexo\` |
| Настройки | `%ProgramData%\karexo\karexo.env` - читают только SYSTEM и администраторы |

Docker не нужен: на Windows он тянет WSL2 и лицензию Docker Desktop для организаций, а инстанс
на десять человек этого не стоит. Сервер лежит **внутри** установщика - в закрытом контуре он
работает так же, как в интернете.

Повторный запуск мастера = обновление: форма подставит уже заданные настройки, кнопка станет
«Применить и перезапустить». Ключ шифрования токенов переживает переустановку.

⚠️ Установщик не подписан - Windows покажет SmartScreen. «Подробнее» → «Выполнить в любом случае».

## 📦 Установка вручную (если скрипт не подходит)

```bash
# 1. взять файлы установки
curl -fsSLO https://raw.githubusercontent.com/mihazzzold/karexo/main/install/docker-compose.yml
curl -fsSLO https://raw.githubusercontent.com/mihazzzold/karexo/main/install/.env.example
cp .env.example .env

# 2. сгенерировать ключ шифрования и вписать его в .env
openssl rand -hex 32

# 3. запустить
docker compose up -d
```

В `.env` обязательны **две строки**: `KAREXO_BASE_URL` (адрес, по которому инстанс будут
открывать) и `KAREXO_TOKEN_KEY` (ключ из команды выше). Остальное можно оставить пустым.

## 🔐 HTTPS

### karexo получает сертификат сам

Если обратного прокси нет - две строки в `.env`, и всё:

```
KAREXO_TLS=auto
KAREXO_TLS_DOMAIN=notes.example.org
```

Понадобится проброс обоих портов - по 80 идёт проверка владения доменом. В `docker-compose.yml`:

```yaml
    ports:
      - "80:8080"
      - "443:443"
```

Сертификаты лягут в том с данными и будут продлеваться сами.

**Свой сертификат** (закрытый контур, свой центр сертификации) - `KAREXO_TLS=file` плюс
`KAREXO_TLS_CERT` и `KAREXO_TLS_KEY`; файлы смонтируйте внутрь контейнера.

⚠️ `auto` не работает при `KAREXO_ALLOW_OUTBOUND=false`: получение сертификата - обращение к
Let's Encrypt. Инстанс откажется стартовать и скажет об этом, а не пойдёт наружу тайком.

### За обратным прокси

Оставьте `KAREXO_TLS=off` (по умолчанию) - тогда шифрование обеспечивает прокси, и это проще
совместить с тем, что у вас уже стоит. Быстрее всего Caddy: он сам получает сертификат.

```caddyfile
notes.example.org {
    reverse_proxy localhost:8080
}
```

После этого поставьте в `.env`:

```
KAREXO_TRUST_PROXY=true
```

⚠️ Эта строка нужна **только** при работе за прокси. Если сервер смотрит в интернет напрямую,
оставьте её пустой: заголовок `X-Forwarded-Proto` присылает клиент, и включённое доверие
позволяет ему заставить сессионную куку уехать по открытому каналу.

## 🔄 Обновление

```bash
docker compose pull && docker compose up -d
```

Данные лежат в отдельном томе и переживают пересоздание контейнера.

⚠️ Пока выпуски предварительные, версия закреплена в `.env` точным номером (`KAREXO_TAG`), и
`pull` сам по себе ничего не обновит - сначала впишите новый номер. Так сделано намеренно:
тег `latest` привёз бы бету всем, кто просто обновляется. Он появится с первым окончательным
выпуском.

Проверить, какая версия сейчас работает:

```bash
curl -s http://localhost:8080/healthz
```

## 💾 Резервные копии

Всё состояние инстанса - в одном томе Docker: база и файлы вложений.

**Вручную** - кнопка «Резервная копия» в разделе «Сервер»: база и вложения одним архивом.

**По расписанию** - две строки в `.env`:

```
KAREXO_BACKUP_DIR=/data/backups
KAREXO_BACKUP_EVERY=24h
KAREXO_BACKUP_KEEP=7
```

**Целиком том** - если хотите забирать копию снаружи:

```bash
docker run --rm -v karexo-data:/data -v "$PWD:/out" alpine \
  tar czf /out/karexo-backup.tar.gz -C /data .
```

## 🏢 Закрытый контур

Одна строка переводит инстанс в режим, где наружу не ходит ни сервер, ни браузер:

```
KAREXO_EDITION=enterprise
```

Она включает сразу три вещи: запрет исходящих запросов, регистрацию по приглашению и строгий
CSP. Проверить, в каком режиме инстанс поднялся на самом деле, - ручкой без входа:

```bash
curl -s https://notes.example.org/api/policy
```

Что сервер видит всегда, а что остаётся зашифрованным, - в разделе
[🔒 Приватность и шифрование](../docs/privacy-encryption.md).

## ❓ Если что-то не так

| Симптом | Что смотреть |
|---|---|
| Контейнер перезапускается | `docker compose logs karexo` - при ошибке настройки сервер называет переменную |
| Не приходят письма | Не заданы `KAREXO_SMTP_*`. Проверка настроек - в разделе «Сервер» |
| Приглашение ведёт не туда | `KAREXO_BASE_URL` не совпадает с реальным адресом |
| Просит войти после каждого обновления страницы | Кука не долетает: за прокси нужен `KAREXO_TRUST_PROXY=true`, а сам прокси обязан передавать `X-Forwarded-Proto` |
| Интеграции пропали после переустановки | Сменился `KAREXO_TOKEN_KEY` - старые токены больше не расшифровать, подключите заново |
