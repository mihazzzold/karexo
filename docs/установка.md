# 🚀 Установка karexo на свой сервер

> 📌 **Сверено с поставкой `install/` этого репозитория, 19.11.2026.** Подходит для выпуска 0.3.0: переменные и команды те же, что в поставочных файлах `install/`.

karexo ставится одним контейнером: внутри и сервер, и приложение, и API. Все данные - база и
вложения - лежат в одном томе Docker; отдельная СУБД, Redis и очереди не нужны.

## 📋 Что нужно

| Требование | Значение |
|---|---|
| **Docker** | Docker Engine с плагином Compose v2 (команда `docker compose`, без дефиса) |
| **Операционная система** | Linux или любой контейнерный хост. На Windows и macOS - Docker Desktop |
| **Память** | от **1 ГБ** свободной |
| **Место на диске** | столько, сколько займут заметки и вложения. Одно вложение - до 25 МиБ |
| **Порт** | по умолчанию `8080`, меняется в `.env` |
| **Браузер** | современный Chrome, Edge, Firefox или Safari |

Проверьте, что Docker на месте: `docker --version` и `docker compose version` отвечают версиями.

## 🧭 Два пути установки

| Путь | Чем ставить | Кому |
|---|---|---|
| 🐧 **Скрипт** | [`install/install.sh`](../install/install.sh) - одна команда | обычный сервер: скрипт всё спросит и поднимет стек |
| 🧰 **Вручную** | `docker compose up -d` по своему compose | когда compose уже свой: ansible, CI, нестандартные тома и сеть |
| 🪟 **Мастер Windows** | 🧊 **со страницы выпуска снят** 16.10.2026: не прошёл проверку и не подписан. Код в репозитории, сборка руками - `make installer` | Windows без Docker, когда мастер вернут |

Оба контейнерных пути настраивают одно и то же - переменные `KAREXO_*` в `.env`; инстанс, поднятый
скриптом, дальше обслуживается теми же командами `docker compose`. Файлы поставки:
[`install/README.md`](../install/README.md), [`install/docker-compose.yml`](../install/docker-compose.yml),
[`install/.env.example`](../install/.env.example).

## ⚡ Установка скриптом

```bash
curl -fsSLO https://raw.githubusercontent.com/mihazzzold/karexo/main/install/install.sh
sh install.sh
```

Скрипт написан на `/bin/sh`: работает и на минимальных образах, где нет bash.

| Вопрос | Умолчание | Зачем |
|---|---|---|
| Адрес, по которому открывают karexo | - (обязателен) | уходит в письма и публичные ссылки. С `http://` или `https://`, без слэша на конце |
| Порт на этой машине | `8080` | левый порт проброса; внутри контейнера всегда `8080` |
| Кто может завести аккаунт | `invite` | `open` · `invite` · `closed` |
| Редакция | `self-hosted` | `self-hosted` или `enterprise` |
| Версия образа | из `.env` или `latest` | точный тег - для воспроизводимости |
| SMTP-сервер | Enter - пропустить | без него не уходят коды и приглашения |
| Почта владельца, имя, пароль | Enter - пропустить | **отвечать надо**: см. раздел про владельца |
| Режим HTTPS | `off` | `off` · `auto` · `file` |

Дальше скрипт делает сам: генерирует `KAREXO_TOKEN_KEY` (`openssl rand -hex 32`, без openssl - из
`/dev/urandom`), пишет `.env` с правами `600` (прежний не затирает, а отодвигает рядом), скачивает
`docker-compose.yml`, если его нет, тянет образ (реестр недоступен - берёт уже скачанный), поднимает
стек, ждёт `/healthz` до 30 секунд и заводит владельца той же командой сервера, что и ручная установка.

### 🤖 Неинтерактивно

Секреты передавайте окружением, а не флагами: командная строка видна в истории оболочки и в `ps`.

```bash
KAREXO_SMTP_PASS=... sh install.sh --yes \
    --base-url https://notes.example.org \
    --port 8080 --registration invite \
    --smtp-host smtp.example.org --smtp-user karexo@example.org \
    --owner-email boss@example.org --owner-name "Начальник"
```

| Флаг | Что делает |
|---|---|
| `--yes` | не спрашивать: брать умолчания и флаги |
| `--base-url` `--port` `--tag` `--registration` `--edition` | основные параметры инстанса |
| `--smtp-host` `--smtp-port` `--smtp-user` `--smtp-pass` `--smtp-from` | почта |
| `--tls` `--tls-domain` `--tls-email` `--trust-proxy` | HTTPS и обратный прокси |
| `--owner-email` `--owner-name` | учётка владельца; пароль - только `KAREXO_OWNER_PASSWORD` или вопрос |
| `--license` `--instance-limit` | ключ платной редакции, потолок людей |
| `--offline` | `KAREXO_ALLOW_OUTBOUND=false`, закрытый контур |
| `--update` / `--uninstall` / `--env-only` / `--help` | обновиться / снять стек (данные целы) / только собрать `.env` |

## 👤 Владелец инстанса

**Читать до первого запуска.** В поставке `KAREXO_REGISTRATION=invite`: формы
«Зарегистрироваться» на инстансе **нет**, а пригласить первого человека некому - база пуста.
Инстанс без владельца - это инстанс, в который нечем войти. `install.sh` спрашивает учётку сам;
при ручной установке её заводит сервер:

```bash
printf '%s\n' 'пароль-не-короче-8' | docker compose exec -T karexo \
    karexo-server -create-owner -data /data -owner-email you@example.org
```

| Что | Как |
|---|---|
| Флаги | `-owner-email` (обязателен), `-owner-login` (пусто - из почты), `-owner-name` (пусто - логин) |
| Пароль | только со stdin, не флагом: аргументы видны в `ps` и в `docker inspect`. Не короче 8 символов |
| Почта владельца | помечается подтверждённой сразу: SMTP на этом шаге может быть ещё не настроен |
| Роль | первая учётная запись становится `owner` - правило живёт в `INSERT`, отдельного шага нет |
| Пароль временный | при первом входе веб требует задать свой, до смены пускает только к смене пароля |
| Повторный запуск | на непустой базе ничего не меняет, код возврата `10`. Коды: `0` готово, `1` поломка, `10` учётки уже есть, `11` плохой ввод |

> ⚠️ **Не очищайте строку `KAREXO_REGISTRATION`.** Пустое значение - это умолчание сервера `open`:
> владельцем станет тот, кто **первым** откроет адрес и зарегистрируется. На публичном адресе это
> гонка с любым, кто узнал про инстанс раньше вас.

## 🧰 Установка вручную

```bash
# 1. взять файлы поставки и сделать .env; ключ из openssl вписать в KAREXO_TOKEN_KEY
curl -fsSLO https://raw.githubusercontent.com/mihazzzold/karexo/main/install/docker-compose.yml
curl -fsSLO https://raw.githubusercontent.com/mihazzzold/karexo/main/install/.env.example
cp .env.example .env && openssl rand -hex 32

# 2. поднять стек и завести владельца (раздел выше), затем открыть адрес из KAREXO_BASE_URL
docker compose up -d
```

Compose не поднимется, пока не заданы **две строки**: `KAREXO_BASE_URL` и `KAREXO_TOKEN_KEY`.
Остальное можно оставить пустым: пустое значение означает умолчание.

### 🔧 Что чаще всего меняют

| Переменная | Умолчание | Зачем |
|---|---|---|
| `KAREXO_BASE_URL` | - (обязательна) | адрес инстанса для писем и публичных ссылок |
| `KAREXO_TOKEN_KEY` | - (обязательна) | ключ шифрования токенов. Смена обесценивает сохранённые токены интеграций |
| `KAREXO_PORT` | `8080` | порт на машине. За прокси ставят `127.0.0.1:8080` в самом compose |
| `KAREXO_TAG` | `latest` | версия образа |
| `KAREXO_REGISTRATION` | `invite` | `open` · `invite` · `closed` |
| `KAREXO_EDITION` | `self-hosted` | `self-hosted` · `enterprise` |
| `KAREXO_SMTP_HOST` и соседние | пусто | почта: коды подтверждения, сброс пароля, приглашения |
| `KAREXO_TLS` | `off` | `off` · `auto` · `file` |
| `KAREXO_TRUST_PROXY` | пусто | `true` - только когда впереди обратный прокси |
| `KAREXO_BACKUP_DIR` `/EVERY` `/KEEP` | пусто / пусто / `7` | резервные копии по расписанию |

Полный перечень - **684 строки** с объяснениями в [`install/.env.example`](../install/.env.example):
что значит пустое значение и какие сочетания ломают старт.

> ⚠️ **Compose передаёт в контейнер только то, что перечислено в `environment`.** Переменная,
> которой там нет, в `.env` не подействует - значение молча останется умолчанием. Проверяется
> в «Проверке настроек».

## 🚪 Первый вход и что дальше

Откройте `KAREXO_BASE_URL` - появится экран **«Вход»**. Входите по почте (или логину) и паролю
владельца; временный пароль из `-create-owner` система попросит сменить сразу.

| Дальше | Где |
|---|---|
| Пригласить людей | **Настройки → Пользователи**: создать учётку или пригласить письмом |
| Роли | **Настройки → Роли и доступ**: владелец, администратор, участник. Роль - про администрирование, а не про доступ к чужим страницам |
| Проверить настройки | **Настройки → Сервер и синк**, карточка **«Проверка настроек»** (`GET /api/admin/diagnostics`): красное чинить сразу, жёлтое решать осознанно |

### ✉️ Почта и SMTP

Почта нужна для трёх писем: код подтверждения адреса, код сброса пароля и приглашение в
документ.

| Переменная | Что это |
|---|---|
| `KAREXO_SMTP_HOST` | адрес сервера. **Пусто - письма не уходят** |
| `KAREXO_SMTP_PORT` | `587` (STARTTLS) или `465` (шифрование сразу) |
| `KAREXO_SMTP_USER` / `KAREXO_SMTP_PASS` | логин и пароль ящика; с двухфакторной защитой - «пароль приложения» |
| `KAREXO_SMTP_FROM` | адрес в поле «От кого», обычно на том же домене, что и SMTP |

После правки `.env` - `docker compose up -d`. Проверить отправку можно кнопкой в карточке
«Проверка настроек»: письмо уйдёт **на адрес нажавшего** и никуда больше.

> ⚠️ **Кодов в журнале больше нет.** Раньше без SMTP код подтверждения и код сброса печатались в
> журнал. Сейчас их печатает только `KAREXO_MAIL_LOG_SECRETS`, а этой переменной нет в поставочном
> `docker-compose.yml` - на своём сервере её и не надо включать: журнал читают шире, чем почтовый
> ящик. Значит, без SMTP не подтвердить адрес и не сбросить пароль. Почту человеку владелец может
> подтвердить вручную в разделе «Пользователи».

## 🌐 Свой домен и HTTPS

`KAREXO_BASE_URL` **сам сайт не создаёт**: он нужен, чтобы письма и ссылки вели куда надо. Чтобы
адрес открывался, нужны A-запись в DNS на этот сервер и открытый порт.

| Режим | Когда брать | Что задать |
|---|---|---|
| `KAREXO_TLS=off` | впереди nginx, traefik или Caddy - шифрует он | `KAREXO_TRUST_PROXY=true` |
| `KAREXO_TLS=auto` | прокси нет, домен смотрит в интернет | `KAREXO_TLS_DOMAIN`, при желании `KAREXO_TLS_EMAIL` |
| `KAREXO_TLS=file` | закрытый контур, свой центр сертификации, wildcard | `KAREXO_TLS_CERT`, `KAREXO_TLS_KEY` |

### 🔐 karexo получает сертификат сам

```
KAREXO_TLS=auto
KAREXO_TLS_DOMAIN=notes.example.org
```

Понадобятся **порты 80 и 443** наружу: по 80 идёт проверка владения доменом. В
`docker-compose.yml`:

```yaml
    ports:
      - "80:8080"
      - "443:443"
```

Сертификаты лягут в том с данными (`<данные>/certs`, меняется `KAREXO_TLS_CACHE`) и продлеваются
сами. Порт HTTPS задаёт `KAREXO_TLS_ADDR` (по умолчанию `:443`), а порт из `KAREXO_PORT` остаётся
под редирект и проверку домена. **Свой сертификат** - `KAREXO_TLS=file` плюс пути в `KAREXO_TLS_CERT`
(цепочка целиком) и `KAREXO_TLS_KEY`; других томов в поставочном compose нет, поэтому файлы кладут
в том с данными (например `/data/certs/`).

> ⚠️ `auto` несовместим с закрытым контуром: получение сертификата - обращение к Let's Encrypt.
> При `KAREXO_ALLOW_OUTBOUND=false` инстанс **откажется стартовать** и скажет взять `file`.

### 🧱 За обратным прокси

Оставьте `KAREXO_TLS=off` и спрячьте порт от внешнего мира:

```yaml
    ports:
      - "127.0.0.1:${KAREXO_PORT:-8080}:8080"
```

Caddy - самый короткий путь, сертификат он получит сам:

```caddyfile
notes.example.org {
    reverse_proxy 127.0.0.1:8080
}
```

nginx: karexo держит постоянное соединение (веб-сокет) для синхронизации, поэтому прокси обязан
пропускать `Upgrade`. Без этого заметки перестанут синхронизироваться.

```nginx
server {
    listen 443 ssl;
    server_name notes.example.org;
    ssl_certificate     /etc/letsencrypt/live/notes.example.org/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/notes.example.org/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 26m;
        proxy_read_timeout 3600s;
    }
}
```

После этого в `.env` - `KAREXO_TRUST_PROXY=true`.

> ⚠️ Эта строка нужна **только** за прокси. Если сервер смотрит в интернет напрямую, оставьте её
> пустой: заголовок `X-Forwarded-Proto` присылает клиент, и включённое доверие позволит ему
> заставить сессионную куку уехать по открытому каналу. Число прокси перед сервером -
> `KAREXO_TRUSTED_PROXY_HOPS` (по умолчанию `1`, `2` - если впереди ещё Cloudflare).

## 🏛️ Редакции и лицензия

| `KAREXO_EDITION` | Что это значит |
|---|---|
| `self-hosted` (по умолчанию) | обычный инстанс: наружу ходит по своим настройкам, регистрация из `.env` |
| `enterprise` | разом включает три вещи: **запрет исходящих**, регистрацию по приглашению и строгий CSP |

По исходящим `enterprise` - то же самое, что `KAREXO_ALLOW_OUTBOUND=false`, только одной строкой.
Проверить, в каком режиме инстанс поднялся **на самом деле**, можно ручкой без входа: `curl -s
https://notes.example.org/api/policy` - ответ покажет `"allowOutbound"` и поле `license`.
Нераспознанное значение сводится к `self-hosted`: падать на опечатке нельзя.

**Лицензия платной редакции** - подписанный ключ-файл Ed25519. Проверяется **оффлайн**, наружу
ничего не уходит, в закрытом контуре работает так же.

| Переменная | Что делает |
|---|---|
| `KAREXO_LICENSE` | сам ключ строкой или путь к файлу. Пусто - бесплатная установка `self-hosted` |
| `KAREXO_LICENSE_ENFORCE` | `true` - без действующего ключа инстанс **не запустится**. По умолчанию мягко: расхождение видно в журнале и в `/api/policy`, работа идёт |
| `KAREXO_LICENSE_CHECK` | раз в сутки спрашивает, жив ли ключ - единственный способ отозвать лицензию. В `enterprise` выключено навсегда |
| `KAREXO_LICENSE_CHECK_URL` | свой шлюз проверки вместо нашего |

- Без действующего ключа потолок - **5 человек**; `0` в подписи означает «без ограничения». Потолок
  не даёт завести **нового** человека, но никого не выгоняет и не мешает работать.
- Ключ можно положить через интерфейс, в **«Сервер и синк»**: замена не требует перезапуска, но
  названную в ключе редакцию инстанс применит только после перезапуска. Поле `license` в
  `/api/policy`: `none`, `valid`, `expired` или `invalid`.

## 🤖 Коннектор claude.ai (по желанию)

claude.ai может ходить в ваш karexo как в источник знаний. Включается `KAREXO_MCP_UPSTREAM` -
адресом моста MCP в вашей сети (в поставочный compose мост не входит, это отдельный контейнер).
Пусто - коннектора нет: `/mcp`, `/.well-known/oauth-*` и `/oauth/*` отвечают `404`. В claude.ai
вставляется один адрес - `<KAREXO_BASE_URL>/mcp`, и инстанс должен быть виден из интернета по
`https`; токен подключения виден в «Подключить ИИ-агента» и отзывается оттуда же.

> ⚠️ Если `KAREXO_MCP_UPSTREAM` задан, а `KAREXO_BASE_URL` пуст, сервер не стартует и пишет об
> этом строку в журнал.

## 🔄 Обновление

Раз в сутки инстанс спрашивает у GitHub, вышла ли новая версия, и показывает это владельцу и
администратору. **Ничего не скачивает и не запускает сам** - решение и команда за человеком.
Управление: `KAREXO_UPDATES_OFF=true` (выключить), `KAREXO_UPDATES_CHECK`, `KAREXO_UPDATES_REPO`
(откуда брать список). В закрытом контуре проверка гаснет вместе с исходящими.

```bash
./install.sh --update            # или вручную:
docker compose pull && docker compose up -d
```

Схема базы досоздаётся сама при старте, том с данными переживает замену образа. После обновления
загляните в «Проверку настроек»: новая версия могла завести переменную, которой в вашем `.env`
ещё нет.

| `KAREXO_TAG` | Кому |
|---|---|
| `latest` (в `.env.example`) | окончательный выпуск; `docker compose pull` приносит свежий. Теги с дефисом (`beta`, `rc`) в `latest` не попадают |
| точный тег, например `v0.3.0` | 🔒 инстанс с рабочими данными: версия меняется только когда вы сами впишете другую |

**Откат** - образом предыдущей версии: впишите прежний тег в `KAREXO_TAG` и сделайте
`docker compose up -d`. Базу вниз по версиям не откатывают: новые колонки старому серверу не
мешают, но записанное новой версией он не покажет. Сломались после обновления - возвращайтесь из
копии, снятой до него.

**Клиенты** обновляются отдельно: веб приезжает с сервером (вкладка предложит обновиться), десктоп
и Android ставят новую версию сами по манифесту.

## 💾 Резервные копии и восстановление

Всё состояние инстанса - том `karexo-data`, каталог `/data`: база `karexo.db`, служебные
`karexo.db-wal` и `karexo.db-shm`, каталог вложений `blobs/`.

| Способ | Как |
|---|---|
| 🖱️ **Вручную** | **Настройки → Сервер и синк → «Скачать копию»**: база и вложения одним архивом. Может только владелец, каждое скачивание попадает в журнал действий, не больше трёх выгрузок в час |
| ⏰ **По расписанию** | три строки в `.env` (ниже) |
| 📦 **Том целиком** | `tar` по тому, если копию надо забирать снаружи |

```
KAREXO_BACKUP_DIR=/data/backups
KAREXO_BACKUP_EVERY=24h
KAREXO_BACKUP_KEEP=7
```

Расписание выключено, пока не заданы `DIR` и `EVERY`. Первая копия снимается не сразу после старта,
а через интервал. Свежая копия сразу проверяется чтением целиком и открытием базы: не прошла -
удаляется. `KEEP` считает **число файлов**, а не дни; мало места - круг пропускается с записью в лог.

Вручную то же самое одной строкой:

```bash
docker run --rm -v karexo-data:/data -v "$PWD:/out" alpine tar czf /out/karexo-backup.tar.gz -C /data .
```

**Проверить копию** (бинарь лежит в образе, сервер при проверке не поднимается):

```bash
docker cp karexo-backup.zip karexo:/data/check.zip
docker exec karexo karexo-server -verify-backup /data/check.zip
```

Ответ «копия годна» и код возврата `0`: архив читается целиком и база из него открывается.

**Восстановление:** проверить архив командой выше → остановить инстанс (именно остановить, а не
перезапустить позже) → положить `karexo.db` в каталог данных, содержимое `blobs/` в каталог
вложений (раскладку внутри `blobs/` не менять: файл лежит по `ab/cd/<id>`) → убрать старые
`karexo.db-wal` и `karexo.db-shm`, они относятся к другой базе → поднять инстанс той же или более
новой версии и проверить вход, страницу с вложением, «Проверку настроек» и журнал действий.

> ⚠️ Копия не спасает **E2E-заметки**: парольная фраза живёт у человека, а не на сервере. И если
> `KAREXO_TOKEN_KEY` не задан, ключ шифрования токенов лежит внутри той же базы - такой архив
> храните как секрет.

## 🪵 Журналы и `/healthz`

Журнал и состояние: `docker compose logs -f karexo` и `docker compose ps` (там же healthcheck),
последние строки - `docker compose logs --tail 50 karexo`.

| Переменная | Что делает |
|---|---|
| `KAREXO_LOG_LEVEL` | `debug` · `info` · `warn` · `error`. Пусто - `info` |
| `KAREXO_LOG_FILE` | путь к файлу: те же записи ещё и построчным JSON, права `0600`. Пусто - только stdout |

```bash
curl -s http://localhost:8080/healthz
# {"status":"ok","version":"v0.3.0"}
```

`/healthz` отвечает без входа и показывает версию - по ней видно, что обновление доехало. Туда же
ходит healthcheck compose. Расшифровка режима и лицензии - `/api/policy`.

## 📴 Оффлайн и закрытый контур

Машина не видит ни интернета, ни нашего реестра образов - есть отдельная поставка архивом: образ,
`docker-compose.yml`, `.env.example`, `install.sh` и инструкция. Полный текст:
[`install/OFFLINE.md`](../install/OFFLINE.md).

```bash
docker load -i karexo-image.tar.gz
sh install.sh --offline --tag <тег, который показал docker load>
```

`--offline` ставит `KAREXO_ALLOW_OUTBOUND=false`: инстанс не обратится ни к одному внешнему адресу,
а скрипт ничего не скачивает - compose лежит рядом с ним в архиве. Что в контуре работать не будет
и почему - таблица в `install/OFFLINE.md`.

> ⚠️ **Закрепите версию тегом.** Без `--tag` compose пойдёт в реестр за образом, которого в
> контуре нет. Обновление в контуре: принести новый архив, `docker load`, `sh install.sh --update`.

## 🆘 Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| 🔌 `port is already allocated` | порт занял другой сервис. Поставьте `KAREXO_PORT=8095` и новый адрес в `KAREXO_BASE_URL`, затем `docker compose up -d`. Внутри контейнера порт всегда `8080` |
| 🚪 На экране только «Вход», регистрации нет | так и задумано: `invite`. Владельца заводит `-create-owner` |
| 📭 Письма не уходят | пуст `KAREXO_SMTP_HOST` либо неверные логин и порт. В журнале строка `[smtp] письмо на ... не отправлено: ...` с причиной; часто нужен «пароль приложения», а не пароль аккаунта |
| 🔐 HTTPS не поднимается | `auto` требует домен, порты 80 и 443 наружу и разрешённые исходящие. В контуре - `file` или `off` плюс прокси. Причина отказа называется в журнале |
| 🔁 Контейнер перезапускается | `docker compose logs --tail 50 karexo`: при ошибке настройки сервер называет саму переменную. Частые причины - пустой `KAREXO_BASE_URL`, кривой `KAREXO_TLS`, `KAREXO_MCP_UPSTREAM` без адреса |
| 🏠 Открывается на сервере, но не с других машин | в compose остался `127.0.0.1`, закрыт порт в межсетевом экране либо в адресе чужой порт |
| 🔑 Просит войти после каждого обновления страницы | кука не долетает: за прокси нужен `KAREXO_TRUST_PROXY=true`, а сам прокси обязан передавать `X-Forwarded-Proto` |

**Интеграции пропали после переустановки.** Сменился `KAREXO_TOKEN_KEY`: старые токены больше не
расшифровать, подключите заново.

**Забыт пароль владельца.** Сброс идёт кодом по почте (действует 15 минут). Без настроенного
SMTP восстановить пароль нечем: кода в журнале больше нет. Единственный путь - завести почту
(`KAREXO_SMTP_*`, перезапуск) и запросить сброс ещё раз.

**Данные не синхронизируются (в шапке `OFFLINE`).** Проверьте `docker compose ps` и `/healthz`.
Сразу после установки прокси - почти всегда не пропущены заголовки `Upgrade` и `Connection`; правки
при этом не теряются, karexo офлайн-первый и досылает их сам.
