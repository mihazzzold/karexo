| Версия | Дата | Чем важен |
|---|---|---|
| **0.3.0** | 19.11.2026 | Два месяца работы после 0.1.1: GitLab, агенты и MCP, мобильная версия, окно строк в базах, уплотнение журнала правок, безопасность входа. На странице выпуска - `docker-compose.yml`, `env.example`, `install.sh` и архив для закрытого контура |
| **0.1.1** | 23.09.2026 | Первый финальный (не бета) выпуск: ИИ переехал в чат, календарь пошёл в обе стороны, документы находятся серверным поиском, установка одной командой `install.sh`, английский по автоопределению браузера |
| **0.0.2-beta** | 19.08.2026 | Выпуск ради безопасности входа: если был включён вход через GitHub - обновиться стоило сразу |
| **0.0.1-beta** | 18.08.2026 | Первая версия, которую можно скачать: нумерация начата заново, поставка без сборки из исходников - Docker и мастер Windows |

Приложение для Android выходит **отдельной сборкой** со своим номером (`0.2.2`, 19.11.2026) и
своей страницей выпуска: APK внутри - оболочка вокруг вашего инстанса, поэтому содержимое
обновляется вместе с сервером, а само приложение - своим файлом. Поэтому номер сервера выше
номера приложения: это две разные линейки.

Вложения к выпуску - вещь необязательная. Готовые файлы (APK, установщик Windows) прикладывались
не ко всем выпускам: у **0.1.1** вложений нет. Сервер ставится скриптом или `docker compose`,
приложение - прямо из браузера; как именно - в [инструкции по установке](../установка.md).

## 🔢 Что означает номер

Номер состоит из трёх чисел: **МАЖОР.МИНОР.ПАТЧ**, например `0.3.0`.

| Часть номера | Когда меняется | Что это значит для вас |
|---|---|---|
| **МАЖОР** (первое число) | Крупные изменения, несовместимые с прошлым | Перед обновлением стоит прочитать заметки к выпуску |
| **МИНОР** (второе) | Появились новые возможности | Обновление безопасное, добавилось новое |
| **ПАТЧ** (третье) | Только исправления | Обновляйтесь смело |

> ⚠️ Пока первое число - **0**, продукт молодой. Это значит, что заметные изменения
> могут приезжать и в минорных выпусках. Смотрите список изменений перед обновлением.

В именах тегов и образов перед номером стоит буква `v`: `v0.3.0`.

### 🧭 Нумерация один раз начиналась заново

В списке изменений рядом с последним финальным выпуском лежат `0.2.3`, `0.2.2`, `0.2.1`,
`0.2.0-beta.2` и `0.2.0-beta.1` от 30.07-18.08.2026 - это **не опечатка и не продолжение**: та
линейка `0.2.x` была внутренней и отдельными установочными файлами не публиковалась. Публичная
нумерация начата заново 18.08.2026 с `0.0.1-beta`; `0.1.0` от 14.07.2026 - первый целостный MVP,
который тоже не публиковался. Поэтому в CHANGELOG `0.0.2-beta` стоит выше `0.2.3`, а `0.3.0` выше `0.2.0-beta.2`: порядок там по дате, а не по номеру.

Ещё одно следствие: **суффикс `-beta` значит предварительный выпуск**. Такой выпуск не получает
тег `latest` у образа, и на «домашнюю» установку он сам не приедет.

## 🔍 Какая версия у меня

Два способа:

1. **В приложении** - «Настройки» → «О программе». Там же кнопка проверки соединения с сервером.
2. **Запросом к серверу** - адрес `/healthz` отвечает JSON вида:

   ```json
   { "status": "ok", "version": "v0.3.0" }
   ```

Если вместо номера версии вы видите `dev`, значит сервер собран из исходников вручную,
без указания версии, - это нормально для самостоятельной сборки.

## 🐳 Где брать образы

karexo распространяется готовым **Docker-образом**: `ghcr.io/mihazzzold/karexo`. На каждый выпуск
публикуются:

- образ в **GitHub Container Registry (`ghcr.io`)** - под точным номером версии (`v0.3.0`);
- тег `latest` - но **только для окончательных выпусков**: тег с дефисом (`v0.2.0-beta.1`) его не
  получает, `latest` в этом случае остаётся на прошлом финальном выпуске;
- страница выпуска со списком изменений.

| Тег образа | Кому подойдёт |
|---|---|
| `v0.3.0` и другие точные номера | 🔒 **Инстанс с рабочими данными.** Версия зафиксирована: `docker compose pull` ничего не меняет, пока вы сами не впишете другой тег |
| `latest` | 🧪 Знакомство и домашняя установка. Стоит в готовом `docker-compose.yml` и в `KAREXO_TAG` по умолчанию, чтобы первый запуск обошёлся без правок; `docker compose pull` приносит последний выпуск - в том числе такой, заметки к которому вы ещё не читали |

> 🏷️ `latest` - это последний **выпуск**, а не последние наработки. Пока новая версия не вышла,
> `latest` указывает на тот же образ, что и свежий номерной тег.

Точный адрес образа и команда запуска - в [инструкции по установке](../установка.md).

## ⬆️ Как обновиться

Коротко:

1. Посмотрите в [CHANGELOG.md](../../CHANGELOG.md), что изменилось между вашей версией и новой.
2. Сделайте резервную копию.
3. На `latest` - забрать свежий образ и перезапустить контейнер:

   ```bash
   docker compose pull && docker compose up -d
   ```

   На точном номере - сначала поменять `KAREXO_TAG` в `.env` на новый номер, потом те же две
   команды.
4. Данные (база и вложения) хранятся в отдельном томе и при смене образа никуда не деваются.

Проверить, что обновление доехало, можно двумя способами из раздела «Какая версия у меня»: ответом
`/healthz` или строкой в «Настройках» → «О программе».

Готовые команды - в разделе [«Обновление»](../установка.md) инструкции по установке.

> 💾 Резервная копия - не «хорошая привычка», а условие: **откат на предыдущую версию
> не гарантирован**, потому что новая версия могла обновить структуру базы. Возвращаться
> придётся из копии, сделанной до обновления. В самом приложении есть ещё
> «Экспорт всего пространства» в ZIP - быстрый запасной вариант на уровне содержимого.
