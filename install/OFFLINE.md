# 🔌 Установка без интернета

Для контура, где машина не видит ни интернета, ни нашего реестра образов. Всё, что нужно,
лежит в этом архиве - скачивать по ходу установки ничего не придётся.

---

## 🐧 Linux и любой контейнерный хост

В архиве: образ, `docker-compose.yml`, `.env.example`, `install.sh` и эта инструкция.

```bash
# 1. загрузить образ из файла
docker load -i karexo-image.tar.gz
```

```bash
# 2. поставить: скрипт спросит адрес и порт, ключ шифрования сгенерирует сам
sh install.sh --offline --tag <тег, который показал docker load>
```

`--offline` ставит `KAREXO_ALLOW_OUTBOUND=false`: инстанс не обратится ни к одному внешнему
адресу. Скрипт ничего не скачивает - `docker-compose.yml` лежит рядом с ним в архиве.

⚠️ **Закрепите версию тегом**: без `--tag` compose пойдёт в реестр за образом, которого в
контуре нет.

Вручную то же самое: `cp .env.example .env`, заполнить `KAREXO_BASE_URL` и `KAREXO_TOKEN_KEY`
(`openssl rand -hex 32`), затем `docker compose up -d`.

## 🪟 Windows

> 🧊 Мастер со страницы выпуска снят 16.10.2026 (не проверен, без подписи кода) - см. `README.md`.

Принесите `karexo_<версия>_windows_server_setup.exe` и запустите. Мастер несёт сервер **внутри
себя** и в интернет не ходит: форма → служба Windows → работающий инстанс. Docker не нужен.

В форме отметьте «Закрытый контур» - это тот же `KAREXO_ALLOW_OUTBOUND=false`.

---

## 🔄 Обновление в контуре

**Docker:** принесите новый архив, `docker load -i karexo-image.tar.gz`, затем
`sh install.sh --update` (или смените `KAREXO_TAG` в `.env` и `docker compose up -d`).

**Windows:** принесите установщик новой версии и запустите. Мастер сам остановит службу,
подменит файл и запустит снова; данные, настройки и ключ шифрования не тронет.

---

## 🔐 Что важно для закрытого контура

Одна строка в настройках переводит инстанс в режим, где наружу не ходит ни сервер, ни браузер:

```
KAREXO_EDITION=enterprise
```

Она включает сразу три вещи: запрет исходящих запросов, регистрацию по приглашению и строгий
CSP. Проверить, в каком режиме инстанс поднялся **на самом деле**, - ручкой без входа:

```bash
curl -s http://localhost:8080/api/policy
```

Ответ покажет `"allowOutbound": false`.

Что сервер видит всегда, а что остаётся зашифрованным, - в разделе
[🔒 Приватность и шифрование](../docs/privacy-encryption.md).

⚠️ **Что в закрытом контуре работать не будет и почему:**

| Не работает | Причина |
|---|---|
| Предпросмотр ссылок-закладок | Это запрос к чужому сайту; ручка отвечает `403 policy.outbound_disabled` |
| Вставки YouTube, Vimeo, Figma | Рамка тянет чужой домен; блок показывает ссылку вместо неё |
| Вход через GitHub, выгрузка в репозиторий | Обращение к `github.com`. Работает с GitHub Enterprise Server: задайте `KAREXO_GITHUB_AUTH_HOST` и `KAREXO_GITHUB_API_HOST` на свой домен |
| Уведомления в Telegram | Облачный сервис. Вебхук и Mattermost внутри вашей сети - работают |
| AI-функции с облачной моделью | Браузер обращается к провайдеру напрямую. Работает с моделью в вашей сети (Ollama, LM Studio, корпоративный шлюз) - укажите её адрес в настройках AI |
| Письма | Работают: SMTP-шлюз ваш, он внутри контура |
