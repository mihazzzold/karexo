# 🚀 Установка karexo на свой сервер

karexo - самохостируемая база знаний: заметки живут на вашем сервере, а не в чужом облаке.

Устанавливается одним контейнером. Внутри - сервер, который сразу отдаёт и приложение, и API;
все данные лежат в одном файле базы. Ни отдельной СУБД, ни очередей, ни дополнительных сервисов
поднимать не нужно.

> Вся установка - это два файла, одна команда и регистрация первой учётной записи.

---

## 📋 Что нужно

| Требование | Значение |
|---|---|
| **Docker** | Docker Engine с плагином Compose v2 (команда пишется `docker compose`, без дефиса) |
| **Операционная система** | Любая, где работает Docker: Linux, Windows, macOS |
| **Свободный порт** | По умолчанию `8080` - можно поменять |
| **Место на диске** | Столько, сколько займут ваши заметки и вложения. Одно вложение - до 25 МБ |
| **Браузер** | Современный Chrome, Edge, Firefox или Safari |

Проверить, что Docker на месте:

```bash
docker --version
docker compose version
```

Если обе команды что-то ответили - можно продолжать.

> 🪟 **Про командную строку.** Сами команды `docker …` одинаковы во всех системах, а обвязка вокруг
> них - нет. Примеры ниже написаны для **bash** (Linux, macOS, WSL). Если вы в **PowerShell**
> на Windows, замените:
>
> - поиск по журналу: вместо `grep текст` - `Select-String текст`, вместо
>   `grep -E "первое|второе"` - `Select-String "первое|второе"`;
> - текущая папка: вместо `"$PWD:/backup"` - `"${PWD}:/backup"`;
> - сегодняшняя дата в имени файла: вместо `$(date +%F)` - `$(Get-Date -Format yyyy-MM-dd)`;
> - запрос к серверу: вместо `curl` - `curl.exe` (в PowerShell 5 `curl` - это совсем другая команда);
> - обратный слеш `\` в конце строки: в PowerShell переносов нет, пишите команду одной строкой.
>
> Самые нужные команды продублированы для PowerShell прямо по месту.

## ⚡ Запуск

### 1. Возьмите два файла: `docker-compose.yml` и `.env`

Оба лежат в папке `install/` этого репозитория. Проще всего склонировать его целиком:

```bash
git clone https://github.com/mihazzzold/karexo.git
cd karexo/install
cp .env.example .env
```

Не хотите клонировать - создайте пустую папку, скачайте в неё `install/docker-compose.yml`
и `install/.env.example` кнопкой «Download raw file» и там же сделайте копию под именем `.env`.

### 2. Загляните в `.env`

Минимум, что стоит проверить, - порт и адрес:

```ini
KAREXO_PORT=8080
KAREXO_BASE_URL=http://localhost:8080
```

Почту можно настроить позже - karexo прекрасно работает и без неё (см. раздел про SMTP).

### 3. Запустите

```bash
docker compose up -d
```

Docker скачает образ и поднимет контейнер. Проверить, что всё живо:

```bash
docker compose ps          # состояние контейнера
docker compose logs karexo # журнал сервера
```

В журнале должна появиться строка вида:

```
karexo server v0.1.0 listening on :8080 (web="/srv/web", data="/data")
```

### 4. Откройте в браузере

```
http://<адрес-вашего-сервера>:8080
```

Если ставили на свой компьютер - просто `http://localhost:8080`.

## 👤 Первый вход

При первом открытии karexo покажет экран входа. Нажмите **Регистрация** и заполните форму:

| Поле | Требования |
|---|---|
| **Логин** | латинские строчные буквы, цифры и `_`, от 3 до 20 символов |
| **Почта** | ваш обычный почтовый адрес |
| **Пароль** | не короче 8 символов |

> 🔑 **Первая зарегистрированная учётная запись становится владельцем инстанса.**
> Регистрируйтесь первым: владелец в инстансе один и не меняется. Именно он раздаёт роли,
> заводит и удаляет учётные записи.

> ⚠️ Форма регистрации открыта для всех, кто может открыть адрес инстанса, - отдельного
> переключателя «закрыть регистрацию» пока нет. Если инстанс смотрит в интернет, а посторонние
> учётные записи вам не нужны, ограничьте доступ снаружи: межсетевым экраном, VPN или
> ограничением по адресам на обратном прокси.

После регистрации вы сразу окажетесь внутри - вход выполняется автоматически.

### Подтверждение почты

Сразу после регистрации karexo отправляет на указанный адрес код подтверждения (действует 30 минут).
В верхней части приложения появляется полоска «Подтвердите почту» с кнопкой **Ввести код** -
она же отправляет свежий код.

Если почта ещё не настроена, письмо никуда не уйдёт, а код запишется в журнал сервера:

```bash
docker compose logs --tail 20 karexo | grep email-verify
# [email-verify] код для you@example.com: 123456
```

В PowerShell то же самое:

```powershell
docker compose logs --tail 20 karexo | Select-String email-verify
```

Работать в karexo можно и не подтверждая почту - но проверьте, что адрес указан без опечатки:
именно на него придёт код, если вы забудете пароль.

### Что дальше умеет владелец

Всё управление - в **Настройках** (шестерёнка), раздел **Администрирование**:

| Раздел | Зачем |
|---|---|
| **Пользователи** | завести или пригласить сотрудника, подтвердить почту, заблокировать, задать квоту хранилища, удалить |
| **Группы** | объединить людей, чтобы выдавать доступ к документам сразу группе |
| **Роли и доступ** | назначить администраторов и выбрать роль, которую получают новые учётные записи |
| **Сервер и синк** | адрес сервера, состояние синхронизации, сколько занято хранилища |

Ролей в инстансе три: **владелец** (может всё), **администратор** (управляет обычными участниками)
и **участник** (только свои документы и то, чем с ним поделились). Роль в инстансе не даёт доступа
к чужим заметкам - доступ выдаётся отдельно на каждый документ.

## ✉️ Настройка почты (SMTP)

Почта нужна для четырёх писем:

- код подтверждения почты (действует 30 минут);
- код сброса пароля (действует 15 минут);
- приглашение в документ для человека, который ещё не зарегистрирован;
- еженедельный дайджест - его человек включает сам в **Настройках → Уведомления**, и уходит он
  только на подтверждённый адрес.

**Без настроенной почты karexo работает.** Письма просто не отправляются, а коды пишутся в журнал
сервера - владелец инстанса всегда может их оттуда прочитать. Для установки «для себя» этого хватает.

### Переменные в `.env`

| Переменная | Что это | Пример |
|---|---|---|
| `KAREXO_SMTP_HOST` | адрес почтового сервера. **Пусто = письма не отправляются** | `smtp.example.com` |
| `KAREXO_SMTP_PORT` | порт: `587` - шифрование через STARTTLS, `465` - шифрование сразу. Пусто = `587` | `587` |
| `KAREXO_SMTP_USER` | логин ящика. Пусто = отправка без авторизации | `karexo@example.com` |
| `KAREXO_SMTP_PASS` | пароль ящика (у многих провайдеров - отдельный «пароль приложения») | `••••••••` |
| `KAREXO_SMTP_FROM` | адрес в поле «От кого». Пусто = подставится логин | `karexo@example.com` |
| `KAREXO_BASE_URL` | публичный адрес инстанса - из него собираются ссылка в приглашении и ссылка отписки в дайджесте. Пусто = письма уйдут без ссылок | `https://karexo.example.com` |

После правки `.env` перезапустите контейнер:

```bash
docker compose up -d
```

### Как проверить

Откройте экран входа (удобно в приватном окне браузера), нажмите **Забыли пароль?**, укажите свой
адрес и посмотрите журнал:

```bash
docker compose logs -f karexo
```

- письмо ушло - в журнале тихо, письмо в ящике;
- не ушло - появится строка `[smtp] письмо на … не отправлено: …` с причиной;
- почта вообще не настроена - вместо письма строка `[password-reset] код для …`.

## 🔒 HTTPS и обратный прокси

Внутри домашней сети karexo можно открывать по обычному `http://`. Но если инстанс смотрит
в интернет, поставьте перед ним обратный прокси с сертификатом.

> 🔐 Это не только про безопасность канала. Браузеры отдают криптографию (а на ней построен
> **личный E2E-сейф** karexo) только на `https://` и на `localhost`. По адресу вида
> `http://192.168.1.50:8080` шифрование заметок на устройстве работать не будет.

### Спрячьте порт от внешнего мира

Когда впереди стоит прокси, karexo не должен слушать наружу. В `docker-compose.yml` замените
строку с портом на:

```yaml
    ports:
      - "127.0.0.1:${KAREXO_PORT:-8080}:8080"
```

И укажите в `.env` настоящий адрес:

```ini
KAREXO_PORT=8080
KAREXO_BASE_URL=https://karexo.example.com
```

> 🔢 **Один порт в трёх местах.** Прокси должен указывать ровно на то значение, что стоит в
> `KAREXO_PORT`: снаружи люди приходят на `443` к прокси, прокси стучится на
> `127.0.0.1:<KAREXO_PORT>`, а внутри контейнера сервер всегда слушает `8080` и это менять не
> нужно. В примерах ниже `KAREXO_PORT=8080`; поменяли порт - поменяйте его и в конфиге прокси.

### Вариант 1 - Caddy (проще всего, сертификат сам)

`Caddyfile`:

```caddyfile
karexo.example.com {
    # 8080 - это значение KAREXO_PORT из .env
    reverse_proxy 127.0.0.1:8080
}
```

Caddy сам получит и продлит сертификат Let's Encrypt и сам пропустит веб-сокеты.

### Вариант 2 - nginx

karexo держит постоянное соединение (веб-сокет) для синхронизации и уведомлений, поэтому прокси
обязан пропускать заголовки `Upgrade`. Без них заметки перестанут синхронизироваться.

```nginx
# в секции http { … }
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 443 ssl;
    server_name karexo.example.com;

    ssl_certificate     /etc/letsencrypt/live/karexo.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/karexo.example.com/privkey.pem;

    # вложения - до 25 МБ
    client_max_body_size 26m;

    location / {
        # 8080 - это значение KAREXO_PORT из .env
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;

        # обязательно: без этих двух строк не работает синхронизация
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection $connection_upgrade;

        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # долгоживущее соединение синхронизации
        proxy_read_timeout 3600s;
    }
}
```

## ⬆️ Обновление на новую версию

```bash
# 1. Сначала резервная копия (см. следующий раздел) - это правило без исключений
# 2. Забрать свежий образ и перезапустить
docker compose pull
docker compose up -d
```

Контейнер пересоздастся, том с данными останется на месте. Схема базы при первом запуске новой
версии обновляется сама.

### Какую версию ставить

Версия задаётся переменной `KAREXO_VERSION` в `.env`. По умолчанию там точный номер -
`docker compose pull` не подменит его сам, и вы всегда знаете, что у вас работает.

| Значение `KAREXO_VERSION` | Кому подходит |
|---|---|
| Точный номер, например `v0.2.0-beta.1` | 🔒 **Так и оставьте.** Версия меняется только когда вы сами впишете другую |
| `latest` | 🧪 Знакомство и домашняя установка: всегда последний выпуск - в том числе такой, заметки к которому вы ещё не читали |

> ⚠️ Тега `latest` пока **не существует**: последняя версия предварительная (beta), а таким
> `latest` не выдаётся - иначе бета уезжала бы каждому, кто просто обновился. Он появится
> с первым окончательным выпуском.

Проверить, что за версия работает прямо сейчас:

```bash
curl http://localhost:8080/healthz
# {"status":"ok","version":"v0.1.0"}
```

В PowerShell - `curl.exe http://localhost:8080/healthz`. То же самое видно
в **Настройках → О программе**.

> ⚠️ Откат на предыдущую версию не гарантирован: новая версия могла обновить структуру базы.
> Возвращаться нужно из резервной копии, сделанной до обновления.

## 💾 Резервное копирование и восстановление

### Что копировать

Всё, что у karexo есть, - это каталог `/data` внутри контейнера, он же том `karexo-data`.
В нём лежит:

| Файл | Что внутри |
|---|---|
| `karexo.db` | **всё**: заметки, документы, пользователи, доступы, вложения |
| `karexo.db-wal`, `karexo.db-shm` | служебные файлы базы - свежие правки, ещё не слитые в основной файл |

Вложения (картинки, файлы) хранятся внутри той же базы, отдельно их копировать не нужно.

> ⚠️ Копировать `karexo.db` «на живую» нельзя: часть правок в этот момент лежит в файле `-wal`,
> и копия окажется неполной. Поэтому перед копированием контейнер останавливаем - на это уходит
> несколько секунд.

### Резервная копия

```bash
docker compose stop

docker run --rm \
  -v karexo-data:/data \
  -v "$PWD:/backup" \
  alpine tar czf /backup/karexo-$(date +%F).tar.gz -C /data .

docker compose start
```

В текущей папке появится файл вида `karexo-2026-07-30.tar.gz`. Храните копии не на том же диске,
где стоит сервер.

**Windows (PowerShell)** - то же самое одной строкой, с `${PWD}` и датой от `Get-Date`:

```powershell
docker compose stop
docker run --rm -v karexo-data:/data -v "${PWD}:/backup" alpine tar czf "/backup/karexo-$(Get-Date -Format yyyy-MM-dd).tar.gz" -C /data .
docker compose start
```

Такую команду удобно повесить на ежедневное расписание (cron, планировщик задач).

### Восстановление

```bash
docker compose down

docker volume create karexo-data
docker run --rm \
  -v karexo-data:/data \
  -v "$PWD:/backup" \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/karexo-2026-07-30.tar.gz -C /data"

docker compose up -d
```

**Windows (PowerShell)** - то же самое:

```powershell
docker compose down
docker volume create karexo-data
docker run --rm -v karexo-data:/data -v "${PWD}:/backup" alpine sh -c "rm -rf /data/* && tar xzf /backup/karexo-2026-07-30.tar.gz -C /data"
docker compose up -d
```

Подставьте имя своего архива. После запуска откройте karexo и проверьте, что документы на месте.

Если в журнале появились ошибки доступа к файлу базы (`permission denied`), верните файлам
владельца - того пользователя, под которым karexo работает внутри контейнера:

```bash
docker run --rm -v karexo-data:/data alpine chown -R 1000:1000 /data
docker compose up -d
```

`1000` - обычный идентификатор этого пользователя; пока контейнер запущен, точное значение
покажет `docker exec karexo id -u`.

### Чего в резервной копии нет

Если вы включили **личный E2E-сейф**, заметки в базе зашифрованы вашей парольной фразой.
Ни фразы, ни recovery-кода на сервере нет и быть не может - значит, их нет и в резервной копии.
Храните recovery-код отдельно: без него зашифрованные заметки не восстановит никто, включая вас.

## 🗑️ Удаление

```bash
# остановить и убрать контейнер, данные при этом сохранятся
docker compose down

# запустить обратно
docker compose up -d
```

Удалить **вместе с данными** (действие необратимо, сначала сделайте копию):

```bash
docker compose down -v
docker image rm ghcr.io/mihazzzold/karexo:latest   # тег - тот, что стоит у вас в image:
```

## 🆘 Что делать, если…

### 🔌 …порт занят

Симптом: `docker compose up -d` падает с `port is already allocated` или `address already in use`.

Значит, порт 8080 занял другой сервис. Выберите свободный порт в `.env`:

```ini
KAREXO_PORT=8095
KAREXO_BASE_URL=http://localhost:8095
```

и перезапустите:

```bash
docker compose up -d
```

karexo откроется по новому адресу `http://<сервер>:8095`. Порт **внутри** контейнера менять
не нужно - он всегда 8080. Если перед karexo стоит обратный прокси, поправьте новый порт
и в его конфиге: `reverse_proxy 127.0.0.1:8095` у Caddy, `proxy_pass http://127.0.0.1:8095;`
у nginx.

---

### 📭 …не приходят письма

Пройдите по списку сверху вниз:

1. **Проверьте журнал** - там написана настоящая причина:
   ```bash
   docker compose logs karexo | grep smtp
   ```
   PowerShell: `docker compose logs karexo | Select-String smtp`
2. **`KAREXO_SMTP_HOST` пуст** → писем и не будет по замыслу. Коды ищите в журнале:
   ```bash
   docker compose logs karexo | grep -E "password-reset|email-verify|invite"
   ```
   PowerShell: `docker compose logs karexo | Select-String "password-reset|email-verify|invite"`
3. **`сервер не поддерживает AUTH`** → вы указали логин, а сервер авторизацию не предлагает.
   Либо очистите `KAREXO_SMTP_USER` (для внутренних релеев), либо возьмите правильный порт.
4. **Ошибка соединения или таймаут** → неверный хост/порт, либо провайдер вашего сервера
   закрывает исходящие соединения на 25/465/587. Попробуйте другой порт из пары `587` / `465`.
5. **Отказ авторизации** → у почтовых провайдеров с двухфакторной защитой нужен не обычный
   пароль, а отдельный «пароль приложения».
6. **Письма уходят, но не доходят** → загляните в спам и проверьте, что `KAREXO_SMTP_FROM`
   совпадает с ящиком из `KAREXO_SMTP_USER`: чужой адрес отправителя часто режется на приёме.

После каждой правки `.env` - `docker compose up -d`.

### 🔑 …забыт пароль

**Если почта настроена.** На экране входа нажмите **Забыли пароль?**, укажите адрес,
получите код из письма (действует 15 минут) и задайте новый пароль.

**Если почта не настроена.** Код всё равно выписывается - он в журнале сервера.
Запросите сброс на экране входа и посмотрите:

```bash
docker compose logs --tail 50 karexo | grep password-reset
# [password-reset] код для you@example.com: 123456
```

PowerShell: `docker compose logs --tail 50 karexo | Select-String password-reset`

Введите этот код на экране сброса. Способ доступен тому, у кого есть доступ к серверу, - то есть
вам как владельцу инстанса.

**Если пароль забыл сотрудник.** Пароль за него никто не меняет - сотрудник сам нажимает
**Забыли пароль?** и вводит код. Когда почта не настроена, код из журнала достаёт владелец
инстанса и передаёт его сотруднику. В **Настройках → Администрирование → Пользователи** владелец
может дополнительно завершить все сеансы этой учётной записи или временно её заблокировать.

> 🔐 **Парольная фраза личного E2E-сейфа - это не пароль от учётной записи.** Сброс пароля
> от входа её не меняет и не восстанавливает: сервер её никогда не знал. Забыли фразу - остаётся
> только recovery-код, который karexo показывал один раз при включении сейфа.

### 🔄 …данные не синхронизируются

Сначала посмотрите на индикатор синхронизации: в шапке приложения это **SYNCED** (всё в порядке)
или **OFFLINE** (связи с сервером нет), а в нижней строке то же самое словами -
«Синхронизировано» / «Офлайн».

karexo офлайн-первый: правки сохраняются в браузере и уходят на сервер, как только связь
восстановится. Поэтому «OFFLINE» - не потеря данных, а повод разобраться со связью.

Что проверить:

| Симптом | Причина и что делать |
|---|---|
| **OFFLINE сразу после установки обратного прокси** | Прокси не пропускает веб-сокеты. Добавьте в nginx заголовки `Upgrade` и `Connection` (см. раздел про прокси). В Caddy это работает само |
| **OFFLINE и контейнер не отвечает** | `docker compose ps` и `docker compose logs karexo`. Проверьте `curl http://localhost:8080/healthz` - должен вернуть `{"status":"ok",…}` |
| **Правки видны на одном устройстве, но не на другом** | Убедитесь, что оба открывают **один и тот же адрес** сервера и вы вошли под одной учётной записью |
| **Синхронизация встала у конкретного человека** | Возможно, исчерпана квота хранилища. Владелец видит её в **Настройках → Пользователи** (колонка «Хранилище»); `0` - без ограничений |
| **Человек не может войти вовсе** | Учётная запись могла быть заблокирована владельцем - там же, в **Пользователях** |
| **Заметки не открываются после перезагрузки страницы** | Включён личный E2E-сейф: введите парольную фразу, чтобы расшифровать данные на этом устройстве |
| **Ссылка «поделиться» не открывается у коллеги** | Такая ссылка строится из адреса, по которому karexo открыт **у вас**. Если вы работаете по `http://localhost:8080`, у коллеги она не сработает - открывайте инстанс по адресу, который виден всем (домен или IP в сети) |

### 🚫 …страница вообще не открывается

```bash
docker compose ps            # контейнер запущен? колонка STATUS
docker compose logs karexo   # что пишет сервер
curl http://localhost:8080/healthz
```

В PowerShell последняя строка - `curl.exe http://localhost:8080/healthz`.

- контейнер перезапускается по кругу - причина будет в последних строках журнала;
- локально открывается, а с другого компьютера нет - дело в межсетевом экране сервера:
  разрешите входящие соединения на выбранный порт;
- проверьте, что в адресе указан правильный порт из `KAREXO_PORT`.

## 📎 Шпаргалка по командам

| Задача | Команда |
|---|---|
| Запустить | `docker compose up -d` |
| Остановить | `docker compose stop` |
| Перезапустить после правки `.env` | `docker compose up -d` |
| Посмотреть журнал | `docker compose logs -f karexo` |
| Состояние | `docker compose ps` |
| Обновить версию | `docker compose pull && docker compose up -d` |
| Проверить, что сервер жив | `curl http://localhost:8080/healthz` (PowerShell: `curl.exe …`) |
| Удалить контейнер (данные целы) | `docker compose down` |
| Удалить вместе с данными | `docker compose down -v` |
