# 🚀 Установка karexo на свой сервер

База знаний из блоков, которая живёт **на вашей машине**. Ваши заметки не уходят к нам:
мы не видим ни текста, ни того, что инстанс вообще запущен.

**Нужно:** Linux с Docker, 1 ГБ памяти, домен (или адрес в локальной сети).
**Времени:** пять минут.

---

## 📦 Установка

```bash
# 1. взять файлы установки
curl -fsSLO https://raw.githubusercontent.com/mihazzzold/karexo/main/install/docker-compose.yml
curl -fsSLO https://raw.githubusercontent.com/mihazzzold/karexo/main/install/.env.example
cp .env.example .env
```

```bash
# 2. сгенерировать ключ шифрования и вписать его в .env
openssl rand -hex 32
```

Откройте `.env` и заполните **две обязательные строки**: `KAREXO_BASE_URL` (адрес, по которому
инстанс будут открывать) и `KAREXO_TOKEN_KEY` (ключ из команды выше). Остальное можно оставить
пустым - у всего есть разумные умолчания.

```bash
# 3. запустить
docker compose up -d
```

Откройте свой адрес. **Первый зарегистрированный аккаунт становится владельцем инстанса** -
регистрируйтесь сразу, пока этого не сделал кто-то другой.

## 🔐 HTTPS

### karexo получает сертификат сам

Если обратного прокси нет - две строки в `.env`, и всё:

```
KAREXO_TLS=auto
KAREXO_TLS_DOMAIN=notes.example.org
```

Понадобится проброс обоих портов - по 80 идёт проверка владения доменом. В `docker-compose.yml`:

```yaml
    ports:
      - "80:8080"
      - "443:443"
```

Сертификаты лягут в том с данными и будут продлеваться сами.

**Свой сертификат** (закрытый контур, свой центр сертификации) - `KAREXO_TLS=file` плюс
`KAREXO_TLS_CERT` и `KAREXO_TLS_KEY`; файлы смонтируйте внутрь контейнера.

⚠️ `auto` не работает при `KAREXO_ALLOW_OUTBOUND=false`: получение сертификата - обращение к
Let's Encrypt. Инстанс откажется стартовать и скажет об этом, а не пойдёт наружу тайком.

### За обратным прокси

Оставьте `KAREXO_TLS=off` (по умолчанию) - тогда шифрование обеспечивает прокси, и это проще
совместить с тем, что у вас уже стоит. Быстрее всего Caddy: он сам получает сертификат.

```caddyfile
notes.example.org {
    reverse_proxy localhost:8080
}
```

После этого поставьте в `.env`:

```
KAREXO_TRUST_PROXY=true
```

⚠️ Эта строка нужна **только** при работе за прокси. Если сервер смотрит в интернет напрямую,
оставьте её пустой: заголовок `X-Forwarded-Proto` присылает клиент, и включённое доверие
позволяет ему заставить сессионную куку уехать по открытому каналу.

## 🔄 Обновление

```bash
docker compose pull && docker compose up -d
```

Данные лежат в отдельном томе и переживают пересоздание контейнера.

⚠️ Пока выпуски предварительные, версия закреплена в `.env` точным номером (`KAREXO_TAG`), и
`pull` сам по себе ничего не обновит - сначала впишите новый номер. Так сделано намеренно:
тег `latest` привёз бы бету всем, кто просто обновляется. Он появится с первым окончательным
выпуском.

Проверить, какая версия сейчас работает:

```bash
curl -s http://localhost:8080/healthz
```

## 💾 Резервные копии

Всё состояние инстанса - в одном томе Docker: база и файлы вложений.

**Вручную** - кнопка «Резервная копия» в разделе «Сервер»: база и вложения одним архивом.

**По расписанию** - две строки в `.env`:

```
KAREXO_BACKUP_DIR=/data/backups
KAREXO_BACKUP_EVERY=24h
KAREXO_BACKUP_KEEP=7
```

**Целиком том** - если хотите забирать копию снаружи:

```bash
docker run --rm -v karexo-data:/data -v "$PWD:/out" alpine \
  tar czf /out/karexo-backup.tar.gz -C /data .
```

## 🏢 Закрытый контур

Одна строка переводит инстанс в режим, где наружу не ходит ни сервер, ни браузер:

```
KAREXO_EDITION=enterprise
```

Она включает сразу три вещи: запрет исходящих запросов, регистрацию по приглашению и строгий
CSP. Проверить, в каком режиме инстанс поднялся на самом деле, - ручкой без входа:

```bash
curl -s https://notes.example.org/api/policy
```

Полный перечень того, куда продукт может обращаться и чем это гасится, - в документе для
службы безопасности (`docs/security-review.md` и `docs/egress.md`).

## ❓ Если что-то не так

| Симптом | Что смотреть |
|---|---|
| Контейнер перезапускается | `docker compose logs karexo` - при ошибке настройки сервер называет переменную |
| Не приходят письма | Не заданы `KAREXO_SMTP_*`. Проверка настроек - в разделе «Сервер» |
| Приглашение ведёт не туда | `KAREXO_BASE_URL` не совпадает с реальным адресом |
| Просит войти после каждого обновления страницы | Кука не долетает: за прокси нужен `KAREXO_TRUST_PROXY=true`, а сам прокси обязан передавать `X-Forwarded-Proto` |
| Интеграции пропали после переустановки | Сменился `KAREXO_TOKEN_KEY` - старые токены больше не расшифровать, подключите заново |
